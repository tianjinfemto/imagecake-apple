## 1.5 侧载注意（未签名 ipa）

CI 的 `iPadOS · unsigned ipa` job 会产出 `ImageCake-unsigned.ipa`（跳过签名）。
实测产物结构（run 40848702846）：

```
ImageCake.app/                       32 MB
├─ ImageCake                         32 MB（主二进制）
└─ Frameworks/
   └─ onnxruntime.framework          ← 动态 framework
```

**关键：`onnxruntime.framework` 是动态的，不是静态链进主二进制。** 重签工具
必须把这个嵌套的 framework 一起签。Sideloadly / AltStore 通常会自己处理，
但如果你遇到下面两种现象，**先怀疑它**：

| 现象 | 含义 |
|---|---|
| 安装时报 `code object is not signed at all` | 嵌套 framework 没被重签 |
| 装上了但点图标就闪退 | 同上，dyld 加载 `onnxruntime.framework` 失败 |

排查：在 iPad 上看崩溃日志，如果堆栈顶部是 `dyld` 或 `onnxruntime` 相关，
就是签名问题而不是我们的代码。

ipa 本身 8.5MB（zip 压缩后），解压后 32MB——不含任何 AI 权重。

## 2. 批次 1 新功能（逐项，本次重点）

### 2.1 画布缩放 / 平移

| # | 步骤 | 预期 | 重点看 |
|---|---|---|---|
| a | 双指捏合放大 | 以捏合点为中心放大，画面不"乱跑" | **锚点是否稳**：捏住的位置下方内容应该不动 |
| b | 放大到边缘外拖 | 拖不出空白，边缘卡在容器边 | 边界夹紧是否正确 |
| c | 放大到 8× 继续捏 | 停在 800%，不再放大 | 上限生效 |
| d | 双击 | 回到刚好铺满 | 复位 |
| e | 右下角 | 放大时出现百分比，铺满时不出现 | |
| f | 放大后单指拖 | **应该是框选，不是平移** | ⚠️ 这是最可能出问题的地方 |

> **f 是本批最大的风险点**。`DragGesture` 不区分触摸数，单指/双指靠
> `MagnifyGesture` 先置 `isPinching` 来区分。如果双指操作时误触发框选，
> 表现为"缩放时画面闪出一个选框"——需要调手势优先级。
>
> 若手感不顺，退路是加一个「浏览 / 框选」模式开关（多一步操作，但确定）。

### 2.2 三区色轮（调色面板）

| # | 步骤 | 预期 |
|---|---|---|
| a | 选「阴影」，把色轮拖向**右侧**（3 点方向） | 暗部偏**红** |
| b | 拖向**下方**（6 点方向） | 暗部偏**黄绿** |
| c | 拖向**左侧** | 偏**青** |
| d | 拖向**上方** | 偏**紫** |
| e | 拖回圆心 | 染色消失（力度归零），方向记忆保留 |
| f | 只推「高光」，看暗部 | 暗部**一点不动** |

> a–d 四条是方向断言。真机上如果整体镜像了（右→青），说明
> `WheelGeometry.adjust` 的 `atan2` 与 `Canvas.addArc` 方向不一致——
> 但单元测试已覆盖这一层，更可能是**你对手柄位置的心理预期**与实现不同。

### 2.3 八分区 HSL（调色面板）

| # | 步骤 | 预期 |
|---|---|---|
| a | 点「青」色带，饱和度拉到 -100 | 画面里的青色明显变灰/变白 |
| b | 换点「红」色带，饱和度拉到 -100 | 红色**只是变淡，不会全灰** |
| c | 再点「橙」和「品红」，都拉到 -100 | 红色才完全变灰 |

> b 是**设计行为**不是 bug：色相环是闭合的，品红带（320°）与红带（0°）
> 环距只有 40°、橙带 30°，都在 45° 窗口内分摊权重（sumW ≈ 1.444），
> 所以单拉红带只能去掉约 69% 的饱和度。见 `CurveAndToneTests` 里的断言。

### 2.4 降噪 / 锐化（调色面板 → 细节）

| # | 步骤 | 预期 | 重点看 |
|---|---|---|---|
| a | 打开一张暗光噪声明显的图，降噪拉到 60 | 噪点变少，**边缘不糊** | 双重滤波的保边是否明显 |
| b | 边拖边看 | 有 0.3–1 秒延迟可以接受 | ⚠️ **12MP 上可能明显卡顿** |
| c | 锐化拉到 50 | 边缘更硬，高光附近不出现白边 | overshoot 是否被 clamp 住 |
| d | 两个都拉到 100 | 不崩、不出现色块 | 值域溢出 |

> b 是已知代价：5×5 双边滤波是 O(r²)/像素，预览 4MP 约 0.3–0.8 秒。
> 如果卡到不可用，下一步优化是**预览用 3×3、导出用 5×5**。
>
> d 看的是 clamp：值域跑出 0...1 会在编码时被截断成色块。

### 2.5 补光 / 高光柔化（调色面板 → 基础）

| # | 步骤 | 预期 |
|---|---|---|
| a | 补光拉到 80 | 暗部起来，**亮部不动** |
| b | 高光柔化拉到 80 | 高光压下去，**暗部不动** |
| c | 两个都拉到 100 看灰卡 | 不产生色偏（灰的还是灰的） |

### 2.6 导出存相册（iPadOS 专属）

| # | 步骤 | 预期 |
|---|---|---|
| a | 导出 → 「保存到」选「相册」→ 导出 | 首次弹**相册写入**授权框（不是"读取相册"） |
| b | 允许 | 面板关闭，底栏显示「已存入相册 · xx MB」 |
| c | 打开「照片」App | 能看到这张图 |
| d | 重新导出，选「相册」但**拒绝**授权 | 面板不关闭，导出报告里出现 `[photos_denied]` 与去设置的提示 |
| e | 选「两者」 | 先写相册，再弹 Files 保存；相册失败也仍然弹 Files |

> a 看的是权限级别：我们只申请 `.addOnly`，系统文案应该是"添加"而非"读取"。
> 如果弹的是完整相册访问，说明 `PHAccessLevel` 用错了。

### 2.7 文件名模板（导出面板 → 文件名）

| # | 步骤 | 预期 |
|---|---|---|
| a | 默认模板 | 预览类似 `IMG_0001-imagecake.jpg` |
| b | 改成 `{date}_{time}-{stem}.{ext}` | 预览变成 `20261029_170631-IMG_0001.jpg` |
| c | 故意写成 `{stme}`（拼错） | 预览里**原样出现** `{stme}`，且下方红色提示"不认识的占位符" |
| d | 清空模板 | 预览回退成 `imagecake.jpg`（不是 `".jpg"`） |
| e | 导出后用 Files 核对 | 实际文件名与预览一致 |

### 2.8 TIFF-16（导出 → 格式）

| # | 步骤 | 预期 |
|---|---|---|
| a | 选 TIFF 16bit 导出 | 成功，文件较大（未压缩：像素数 × 8 字节） |
| b | 用 macOS 预览 / Photoshop / 其他软件打开 | 能打开，且报告位深是 16bit/通道 |
| c | 检查透明区域 | alpha 保留（不是被填黑或填白） |
| d | 超大图（超 24MP） | 拒绝并报 `[tiff16_too_large]`，不是闪退 |

> b 是这一项的核心。CI 里已经用 ImageIO 读回验证了 16/64 位深与像素，
> 但**换一个非 Apple 的软件**读一次，才能确认这个 TIFF 不是"只有 ImageIO 认"。

### 2.9 边缘去色溢出（AI 面板 → 背景）

| # | 步骤 | 预期 |
|---|---|---|
| a | 先抠图，再启用背景处理，换一个**深色**底 | 主体边缘出现一圈脏边（这是现状） |
| b | defringe 拉到 70 | 脏边明显减轻，**发丝仍是半透明** |
| c | 拉到 100 | 脏边更干净，但**不该出现色斑** |
| d | 看极细的发丝尖 | 找不到实心邻居的地方应原样保留，不是被填成一块 |

> c/d 是这一项最容易翻车的地方：找不到实心邻居时我们是保守保留的，
> 如果真机上出现"头发边缘一块突兀的颜色"，说明搜索半径 3 太大，
> 把另一侧的颜色拉过来了。

## 4. 性能观察点

记下来，作为后续优化的基线：

- [ ] 12MP 图拖曝光滑杆：是否掉帧
- [ ] 12MP 图降噪 60：单次渲染耗时（目标 < 1s）
- [ ] 放大到 8× 拖动画布：是否掉帧
- [ ] 4x 超清一张 12MP：总耗时（分钟级，**必须保持前台**）
- [ ] 32MP 图导出 TIFF-16：耗时与内存峰值（会不会被系统杀）

## 5. 出问题时怎么定位

| 现象 | 先看哪里 |
|---|---|
| 启动闪退 | Xcode → Window → Devices and Simulators → View Device Logs |
| 某一步失败但不崩 | 导出报告 / 底栏状态栏（`[no_model]`、`[photos_denied]`、`[too_large]`…） |
| 画面不对但没报错 | 先确认是不是**预期行为**（见 2.3、2.9 的说明） |
| 只在真机复现 | 记下机型内存（4/6/8GB），导出/超清上限是按物理内存分档的 |

拿不到 Xcode 日志时：iPad 上 设置 → 隐私与安全性 → 分析与改进 → 分析数据，
找 `ImageCake-*.ips`。

## 6. 已知缺口（不是 bug，别当失败记）

- 存不回相册的**读取**（只申请写入权限）
- 旋转/裁剪/透视未实现
- 液化、保护笔刷、仿制图章、本地调节未实现
- 面部关键点、美体、年龄性别未接线
- 拼图、批量、CLI、联机拍摄、XMP、水印边框不在 v1
- 长任务切后台会被挂起（未申请后台执行）
- PNG-16 / TIFF-16 存相册会被照片库转成 8bit（面板里已提示）
