## 1.5 侧载注意（未签名 ipa）

CI 的 `iPadOS · unsigned ipa` job 会产出 `ImageCake-unsigned.ipa`（跳过签名）。
实测产物结构（run 40848702846）：

```
ImageCake.app/                       32 MB
├─ ImageCake                         32 MB（主二进制）
└─ Frameworks/
   └─ onnxruntime.framework          ← 动态 framework
```

**关键：`onnxruntime.framework` 是动态的，不是静态链进主二进制。** 重签工具
必须把这个嵌套的 framework 一起签。Sideloadly / AltStore 通常会自己处理，
但如果你遇到下面两种现象，**先怀疑它**：

| 现象 | 含义 |
|---|---|
| 安装时报 `code object is not signed at all` | 嵌套 framework 没被重签 |
| 装上了但点图标就闪退 | 同上，dyld 加载 `onnxruntime.framework` 失败 |

排查：在 iPad 上看崩溃日志，如果堆栈顶部是 `dyld` 或 `onnxruntime` 相关，
就是签名问题而不是我们的代码。

ipa 本身 8.5MB（zip 压缩后），解压后 32MB——不含任何 AI 权重。

## 2. 批次 1 新功能（逐项，本次重点）

### 2.1 画布缩放 / 平移

| # | 步骤 | 预期 | 重点看 |
|---|---|---|---|
| a | 双指捏合放大 | 以捏合点为中心放大，画面不"乱跑" | **锚点是否稳**：捏住的位置下方内容应该不动 |
| b | 放大到边缘外拖 | 拖不出空白，边缘卡在容器边 | 边界夹紧是否正确 |
| c | 放大到 8× 继续捏 | 停在 800%，不再放大 | 上限生效 |
| d | 双击 | 回到刚好铺满 | 复位 |
| e | 右下角 | 放大时出现百分比，铺满时不出现 | |
| f | 放大后单指拖 | **应该是框选，不是平移** | ⚠️ 这是最可能出问题的地方 |

> **f 是本批最大的风险点**。`DragGesture` 不区分触摸数，单指/双指靠
> `MagnifyGesture` 先置 `isPinching` 来区分。如果双指操作时误触发框选，
> 表现为"缩放时画面闪出一个选框"——需要调手势优先级。
>
> 若手感不顺，退路是加一个「浏览 / 框选」模式开关（多一步操作，但确定）。

### 2.2 三区色轮（调色面板）

| # | 步骤 | 预期 |
|---|---|---|
| a | 选「阴影」，把色轮拖向**右侧**（3 点方向） | 暗部偏**红** |
| b | 拖向**下方**（6 点方向） | 暗部偏**黄绿** |
| c | 拖向**左侧** | 偏**青** |
| d | 拖向**上方** | 偏**紫** |
| e | 拖回圆心 | 染色消失（力度归零），方向记忆保留 |
| f | 只推「高光」，看暗部 | 暗部**一点不动** |

> a–d 四条是方向断言。真机上如果整体镜像了（右→青），说明
> `WheelGeometry.adjust` 的 `atan2` 与 `Canvas.addArc` 方向不一致——
> 但单元测试已覆盖这一层，更可能是**你对手柄位置的心理预期**与实现不同。

### 2.3 八分区 HSL（调色面板）

| # | 步骤 | 预期 |
|---|---|---|
| a | 点「青」色带，饱和度拉到 -100 | 画面里的青色明显变灰/变白 |
| b | 换点「红」色带，饱和度拉到 -100 | 红色**只是变淡，不会全灰** |
| c | 再点「橙」和「品红」，都拉到 -100 | 红色才完全变灰 |

> b 是**设计行为**不是 bug：色相环是闭合的，品红带（320°）与红带（0°）
> 环距只有 40°、橙带 30°，都在 45° 窗口内分摊权重（sumW ≈ 1.444），
> 所以单拉红带只能去掉约 69% 的饱和度。见 `CurveAndToneTests` 里的断言。

### 2.4 降噪 / 锐化（调色面板 → 细节）

| # | 步骤 | 预期 | 重点看 |
|---|---|---|---|
| a | 打开一张暗光噪声明显的图，降噪拉到 60 | 噪点变少，**边缘不糊** | 双重滤波的保边是否明显 |
| b | 边拖边看 | 有 0.3–1 秒延迟可以接受 | ⚠️ **12MP 上可能明显卡顿** |
| c | 锐化拉到 50 | 边缘更硬，高光附近不出现白边 | overshoot 是否被 clamp 住 |
| d | 两个都拉到 100 | 不崩、不出现色块 | 值域溢出 |

> b 是已知代价：5×5 双边滤波是 O(r²)/像素，预览 4MP 约 0.3–0.8 秒。
> 如果卡到不可用，下一步优化是**预览用 3×3、导出用 5×5**。
>
> d 看的是 clamp：值域跑出 0...1 会在编码时被截断成色块。

### 2.8 TIFF-16（导出 → 格式）

| # | 步骤 | 预期 |
|---|---|---|
| a | 选 TIFF 16bit 导出 | 成功，文件较大（未压缩：像素数 × 8 字节） |

### 2.9 边缘去色溢出（AI 面板 → 背景）

| # | 步骤 | 预期 |
|---|---|---|
| a | 先抠图，再启用背景处理，换一个**深色**底 | 主体边缘出现一圈脏边（这是现状） |
| b | defringe 拉到 70 | 脏边明显减轻，**发丝仍是半透明** |

### 2.10 笔刷工具（笔刷面板）

| # | 步骤 | 预期 | 重点看 |
|---|---|---|---|
| a | 切到「笔刷」tab，选「液化」 | 工具高亮，底栏无异常 | 面板入口是否到位 |
| b | 在画布上拖动一段 | 画面内容沿拖动方向被推，拖动时显示蓝色半径圈与方向箭头 | ⚠️ **推的方向是否与拖动一致** |
| c | 撤销（⌘Z / 工具栏） | 液化退回，画面恢复 | 一笔 = 一步历史 |
| d | 选「保护」，涂一片区域 | 涂时显示半透明轨迹，松手后画面不变（保护不改像素） | 轨迹是否跟手 |
| e | 再选「液化」，在保护区域上拖 | **保护区域内像素不动**，区域外正常被推 | 保护掩码是否生效 |
| f | 选「图章」，点「在画布上点一下取样」 | 取样模式开启 | |
| g | 在画布上点一处 | 出现绿色十字标记，取样模式自动关闭 | 锚点位置是否准 |
| h | 在画布上拖动绘制 | 锚点处的内容被搬到笔迹处 | ⚠️ **搬运方向与偏移是否正确** |
| i | 撤销两次 | 图章退回、保护退回 | 撤销栈序 |
| j | 半径拉到 0.15，再涂一笔 | 笔刷范围明显变大 | 参数是否生效 |
| k | 「清除全部笔刷」 | 所有笔迹消失，画面回到调色后状态 | |
| l | 双指捏合放大后单指拖 | **是落笔不是框选**（工具选中时） | ⚠️ 手势优先级 |

> **b 是核心**：液化方向反了是最可能的问题——`LiquifyEngine` 用反向位移场，
> 内容看起来沿拖动方向走。如果真机上方向反了，说明 `from`/`to` 传反了。
>
> **e 是保护的硬测试**：CI 能证算子，但「保护区域上拖液化不动」是接线级
> 的性质，只有真机能看到完整画面。
>
> **l 与 2.1 f 对称**：工具未选时单指拖是框选，工具选中时是落笔。
> 如果双指缩放时误触发落笔，表现为「缩放时画面被液化/涂了一笔」。

### 2.11 挑背景灰点（AI 面板 → 消除/补丁那一行）

| # | 步骤 | 预期 | 重点看 |
|---|---|---|---|
| a | 纯色背景（棚拍背景布 / 天空 / 白墙）上有灰点的照片，点「挑背景灰点」 | 状态栏出现「检出 N 处背景灰点… · [spot-repair:N]」，并生成 N 笔修补笔迹 | N 与肉眼看到的灰点数是否接近；**脸上不应出现任何笔迹** |
| b | 有纹理的背景（草地 / 树叶 / 虚化焦外 / 渐变墙）点一次 | 状态栏 `[spot-repair:none]`，画面零变化 | 这一格最重要：误检会把一片纹理抹掉一块 |
| c | 灰点很多（传感器脏）的一张点一次 | 最多提意 24 处，状态栏带 `[spot-repair:capped]` | 截断必须看得见，不能让人以为"背景只有这 24 个点" |
| d | 还没跑过关键点（没检测到人脸）时点一次 | 状态栏带 `[no_face_box]`；仍然只提意、不自动改画面 | 缺人像 α 时只靠肤色 + 脸框兜，判"可用但别全信" |
| e | 提意后逐笔撤销 / 清除修补笔迹，再导出 | 画面回到原状，导出与预览一致 | 证明它走的是与手动画同一条路（同一 `patch` 阶段） |
| f | 已做过裁剪/调色后点一次 | 判定用的是**当前画面**：裁掉的边缘不会再生成笔迹 | 用原图判还是用当前画面判，差别就在这格 |

> **风险点**：真实照片的"平坦"远比测试夹具复杂 —— 渐变背景、奶油般虚化焦外、婴儿皮肤
> 都可能落进"低方差 + 比邻域暗"的形状里。b/d 两格若出现误检，先按已知缺口记录，
> 不要当场放宽阈值救它：退路是收紧（`darkLimit` 上调 / `flatLimit` 下调），
> 因为漏检只是留个灰点，误检是抹掉一块画面。

| 逐脸力度 | 美妆 → 逐脸力度（先检测关键点） | 合影里选第2张 → 滑到 0 应当完全不动那张脸；画布上「点脸」要能选对人（选中的那张有实线框）。失败：点 A 选中的是 B（下标按脸大小排，脸数变了要重选） | 关键点 |
| 镜片反光去除 | 美妆 → 区域美化 → 镜片祛反光 | 只压镜片上的眩光，不动唇色与彩色镜片边缘，也不把额头/下巴压暗（区域锚在虹膜半径上）。失败：框盖到嘴导致唇色变暗 | 关键点 |
| 换发色 / 祛碎发 | 美妆 → 头发 | 换色后头发高光与阴影必须原样（只染色不掉体积）；祛碎发只啃边缘那圈，发团内部与原背景不动。失败：整片头发变塑料或发际线被啃进一圈 | 关键点定发区 |
| 颈纹 / 妊娠纹 | 笔刷 → 细纹 → 涂脖子/肚子 | 只淡细纹，涂在锁骨阴影或孕肚轮廓上必须没反应。没涂时点名 [no_line_region] | 手涂区域 |
| 渲染耗时诊断 | 工具 → 诊断 → 底栏显示渲染耗时 | 真机 + 全分辨率图上必须看得出**耗在哪一段**（导出报告的 `[perf]` 行同理）。这是性能优化的改前/改后对照来源 | — |
| XMP 导入 | 工具栏「预设」→「读图旁边的 .xmp」/「从 .xmp 导入…」 | 导 Lightroom 写出的 `<图名>.xmp`：曝光/色温/对比/HSL/分区调色必须落到滑杆上，底栏报“XMP 已导入（文件名）”。四条失败路径都要能当场看到令牌：旁边没文件 `[no_xmp_sidecar]`、不是从文件打开的 `[no_xmp_source]`、读不了 `[xmp_unreadable]`、一个键都没映上 `[xmp_no_mapping]`。失败：只弹一句“已导入”而滑杆全零 | 沙箱对图所在目录的访问权 |

> 联机拍摄这一项在 CI 上**只能验决策层**（选设备优先级、回落点名、连拍上限、文件名不撞名）。
> 真机部分需要：用带 entitlement 的签名包（未签名 ipa 没有相机权限也不行），
> 外接相机走 USB/相机适配器或 Wi-Fi。见 §1.5。

## 6. 已知缺口（不是 bug，别当失败记）

这份清单只在“真机上也不该指望它工作”的范围内。任何一条被列为已实现的能力
都应该能在本节找到它的反面，所以每条都带现状说明：

### 6.1 平台与权限限制

- 存不回相册的**读取**（只申请写入权限，`.addOnly`）
- 长任务切后台会被挂起（未申请后台执行）
- PNG-16 / TIFF-16 存相册会被照片库转成 8bit（面板里已提示）
- iPad 侧外接相机（UVC）需要 external-camera entitlement，**未签名 ipa 拿不到**
  → 面板点名 `[no_camera]`；不是厂商联机协议（EDSDK / Imaging Edge 类不在范围）
- 无实时取景，只给回片预览

### 6.2 真的没做（不是验不到）

- **透视校正 / 自动水平**：需消失点与地平线检测（旋转/翻转/裁剪已实现并接线）
- **CLI**：iPadOS 无等价路径，macOS 也没做独立命令工具
- **工程文件类型**：不新建。逐张参数存在图旁边的 `<名字>.imagecake.json` sidecar 里；
  目录授权是会话级的，所以每次要重选目录（参数仍然接得上）
- **重复帧去重与美学分**：`FrameTriage` 只给 5 个确定性轴（清晰/截幅/曝光/眼开/边距），
  不报美学分，也不找同一机位的重复帧
- **106 点关键点与 YuNet 人脸检测两颗备用权重未接线**（人脸走 Vision）

### 6.3 已实现、但只能真机验的部分

这一组不是缺口，是“CI 结构上验不到”：每一条都要在真机上过一遍才能算完成。

- 主观效果：妆容模板、换发色、磨皮质感、逐脸选中的手感、追色是否自然
- 系统硬件路径：联机拍摄（真相机）、手部美化（合成图喂不出 `VNDetectHumanHandPose`）
- AI 权重推理：CI 不下载 660MB 权重，所以 ORT 前向从未跑过
- 性能：共享 runner 的抖动幅度实测 ±34%，5~15% 的优化必须靠真机「工具 → 诊断」的
  `[RELEASE]` 分段读数才能判
- 手势与布局：分屏尺寸、Apple Pencil、权限弹窗（模拟器不是 iPad）
